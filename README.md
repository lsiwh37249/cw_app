v1. 작업자 작업물 빠른 조회 (Read Only)
1. 목적

낮은 생산성을 보이는 작업자의 원인을 빠르게 파악하기 위해,
작업자의 실제 작업물(URL)을 즉시 확인할 수 있는 조회 화면을 제공한다.
이를 통해 작업물 확인에 소요되는 분석 시간을 단축하는 것을 목표로 한다.

2. 문제 상황

현재는 작업자별 작업물을 직접 찾아 확인해야 하며, 이 과정에서 과도한 시간이 소요된다.
또한 운영 중인 메인 DB를 직접 조회할 경우 다음과 같은 문제가 발생할 수 있다.

- 다수 조회로 인한 동시성 이슈
- 조회 트래픽 증가에 따른 읽기 성능 저하

3. 설계 방향

본 기능은 운영 DB와 분리된 읽기 전용 조회 뷰로 구성한다. 빠른 프로토타입 구축을 위해 다음 방식을 채택한다.

- 단일 테이블 기반 구조
- delete + append 방식으로 전체 데이터 갱신
- EC2에서 주기적으로 CSV 업로드

👉 핵심 설계 의도는 **“운영 영향 없이 빠르게 조회 가능한 구조”**이다.

4. 테이블 설계 (RESULT_TABLE)
구분	컬럼
식별	프로젝트ID, 데이터ID
상태	작업 상태, 작업불가여부, 수정 여부
수량	유효 오브젝트 수, 최종 오브젝트 수
작업자	Worker ID, 작업자 닉네임
검수자	Checker ID, 검수자 닉네임
시간	작업 종료일, 검수 종료일, 작업 수정 시간
링크	CO 모니터링 URL

5. 화면(UI) 구성

입력 영역 : Worker ID 또는 작업자 닉네임

결과 영역 (Table) : Worker ID, 작업자 닉네임, 프로젝트ID, CO 모니터링 URL

👉 특정 작업자를 기준으로 작업 목록과 실제 작업물을 즉시 확인하는 데 집중한다.
